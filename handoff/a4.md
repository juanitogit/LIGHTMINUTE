# Handoff — A4 (Protocol runner & Ground console)

## DONE

### `kb/protocols/` (3 protocols, no doses)
`fever_like_syndrome.json`, `co2_headache_cluster.json`, `post_eva_orthostatic.json`
with `{id, title, trigger_patterns[], steps[{text, source_status, source}]}`.

- **Every step is `demo-wording`** with a visible badge. No step has a published source I
  could open, so none is marked `published` — that field is honest, not decorative.
- Steps point at the onboard medical protocol instead of naming drugs; no doses anywhere.
- Steps are phrased for a non-physician and are executable by any crew member (the CMO can
  be the patient).
- `trigger_patterns` are **descriptive strings** that reference engine outputs (syndrome,
  level, hazard panel). The engine/host decides; the runner never evaluates them and never
  invents a threshold.

### `packages/protocol-runner/`
- `runner.js` — implementation, classic script (needed for `file://`).
- `index.js` — the documented ES module: re-exports `mountProtocolRunner` from `runner.js`.
- `style.css`, `demo.html`, `README.md`.
- `mountProtocolRunner(el, {protocolId | protocol, protocolUrl, onStep, onDone}) -> controller`
  (`destroy, next, prev, undo, cannot, restart, setProtocol, getState`).
- One step per screen, ≥64 px targets, per-step + total timer, "can't do this" branch
  (skip / call a crew mate / stop and escalate), undo, keyboard `→ ← C`, ARIA progressbar +
  `aria-live` step text, `demo wording` badge with the source string beside it.

### `apps/ground-console/`
- `index.html` + `src/main.js` + `src/styles.css` — static, no build step.
- Crew list with level (glyph + word + colour), sparklines against the personal 95% band,
  syndrome z, learning state, card source.
- Message queue from each card's `ground_message` + `routing` (priority, expected reply,
  char budget with over-budget flag, `act_onboard_first`).
- Mission profile ISS 0 s / Moon 1.3 s / Mars 3–22 min with an animated light-delay
  timeline and the onboard-first caption (demo policy constants mirrored from
  `ground/delay.py`).
- Consent tiers: vitals / symptoms / behavioural (off by default) with a live
  "what ground receives" preview per message.
- `src/audit-core.js` + `src/audit.js` — SHA-256 chain mirroring `tether_engine/audit.py`
  (sorted keys, compact separators, ASCII-escaped), plus a chain viewer that flags the
  first tampered entry.
- `data/make-sample.py` regenerates `data/sample-scenario.{json,js}` from the engine export.
- `package.json` only marks the folder as ESM for Node tooling; there is still no build.

## INTERFACES I expose

**Protocol runner**
```js
import { mountProtocolRunner } from "./packages/protocol-runner/index.js"; // or runner.js as a classic script
const runner = mountProtocolRunner(el, {
  protocolId: "fever_like_syndrome",        // fetched from ../../kb/protocols/<id>.json
  protocol: inlineProtocolObject,           // or pass the object (required for file://)
  onStep: (e) => auditLog.append("protocol_step", e),
  onDone: (e) => queueSummary(e),
});
```
- `onStep` → `{protocolId, stepIndex, status, tsMs}`, status ∈ `viewed | done | cannot | undo`.
- `onDone` → `{protocolId, completed, startedMs, endedMs, totalMs, steps:[{stepIndex,status,reason,ms}]}`.

**Ground console**
- Reads `data/scenario-<name>.json`, then `../../apps/crew-tablet/public/data/scenario-<name>.json`,
  then `../../apps/crew-tablet/public/demo-data.json`, then the local fixture, then the file picker.
- No API calls, no external requests. Any host can link it: `apps/ground-console/index.html`.

**Audit chain (browser)**
```js
globalThis.TetherAudit.appendEntry(chain, {event, payload, ts}) // -> entry
globalThis.TetherAudit.verifyChain(chain)                       // -> {ok, firstBadIndex, reason}
```

## KNOWN ISSUES
- **`file://` could not be clicked through** in this environment (the browser tool rejects
  `file://` URLs). The pages are built for it (classic scripts, inline fixture, no module
  imports, no `fetch` requirement) but the only exercised path is http. Please open
  `apps/ground-console/index.html` and `packages/protocol-runner/demo.html` by
  double-clicking before the demo.
- `demo.html` inlines a copy of `fever_like_syndrome.json`; if the protocol changes, copy
  the JSON again (noted in its README).
- `data/sample-scenario.json` is a 173 KB fixture duplicated from the engine export.
- `SEP sleep-loss` and `co2_creep` show the same demo export until A1 publishes the real
  `scenario-*.json`; the source line says so.
- The ground console shows routing numbers **as exported** (Mars profile); only the
  timeline is profile-aware. Ledger wording says this on screen.
- Protocol `trigger_patterns` are descriptive; nothing in this repo evaluates them yet.
