# Handoff — A3 (crew tablet UI)

Updated: final pass (build + browser QA done).

## DONE

Crew tablet is a real Vite + React + TypeScript (strict) app in `apps/crew-tablet`,
not a static mock. `npm run build` is green (`tsc -b && vite build`).

- **Data layer** `src/lib/api.ts` — contract-first, API → static → demo:
  - `loadScenario(name)`: `GET /api/scenario/{name}` → `public/data/scenario-{name}.json`
    → `public/demo-data.json` (marks `degraded`).
  - `loadScenarioIndex()`: `/api/scenarios` → `public/data/scenario-index.json` →
    the three planned names (picker marks them “demo data”).
  - `requestCard()`: `POST /api/card`, 15 s timeout, null on failure.
  - `GET /api/health` is probed first; if it fails the API path is disabled for that
    page load, so the static demo is instant and the console is quiet.
  - Nothing is recomputed in the UI: every number, band, z, verdict and level is
    rendered from the payload.
- **Glance** — crew strip (4 members, level + one sentence + z + `learning`), crew
  attribution banner, SVG body silhouette whose regions glow from the engine's
  personal verdicts and open the matching Why view. Region without a reading is
  explicitly muted (not green).
- **Why** — per-indicator tabs (HR / temp / sleep / PVT); personal 95% band chart
  with value line, baseline and Earth range when the export exposes it; syndrome
  strip with alert line 2.33 (labelled demo parameter); three lens cards (Earth,
  space-adapted, personal); disagreement patterns (`hidden_in_range`,
  `expected_for_you`, `mixed`) get a loud banner + one-line explanation; shows
  confidence, `n_seen`, `z`, `p`, HRP risk family and hazard.
- **Act** — Decision Card: headline, what changed, why it matters, tappable
  checklist with progress, escalate-if, monitor chips, KB citation ids,
  `card_source` badge (`DeepSeek · verified` vs `protocol template`), and the
  ground message with char budget and a simulated reply countdown driven by
  `routing.expected_reply_s` / `priority` / `send_now` / `act_onboard_first`.
  Engine urgency is stated as non-negotiable for the explainer.
- **A4 protocol runner is mounted for real**, not a stub: `vite.config.ts` exposes
  `virtual:tether-protocol-runner`, `virtual:tether-protocols` (inline
  `kb/protocols/*.json`) and `virtual:tether-protocol-css`; Act shows an optional
  “Onboard protocol” picker and mounts A4's `mountProtocolRunner` with the inline
  protocol. Missing package = panel disappears, build stays green. Verified in
  browser: title, 9 steps, advancing works.
- **Radiation / Validation** — tolerant renderers for `public/data/validation.json`,
  `public/data/radiation.json` and `/api/llm-stats`; today they show honest empty
  states (“not published yet”, “API offline”) and never estimate a value.
- **Shell** — URL hash state (`#scenario=&crew=&day=&ind=&view=&pres=1`), scenario
  picker, crew pills, day scrubber with play/pause, 5 views, dark default + light
  toggle (persisted), presentation mode, SYNTHETIC DATA + “not a medical device”
  badges in the header **and** a mobile strip, footer with API/data provenance.
- **A11y/UX** — status = icon + text + colour; 44–48 px targets; native checkbox
  checklist; body-map regions are keyboard buttons; skip link; `aria-live` on
  loading/countdown completion; reduced-motion respected; keyboard ←/→ steps the
  day; no horizontal overflow at 390 px.
- **Design tokens** in `packages/ui-kit/tokens.css` (+ README): dark default,
  light, red-shift option, 8-pt spacing, one accent, four status roles.

## INTERFACES I expose / consume

- Consumes exactly `docs/DEMO_DATA_CONTRACT.md`. Tolerates additive optional fields:
  - `indicators[<key>].earth_range: [lo, hi]` → drawn as the Earth band/lines.
  - `crew[<id>].protocol_id`, `meta.protocol_id` or `meta.default_protocol` → preselected
    protocol for A4's runner.
  - `meta.title`, `meta.summary` → titles; otherwise the UI prettifies the name.
- `VITE_API_BASE` (optional) for an absolute API origin; empty = same-origin
  (`vite` proxies `/api` → `127.0.0.1:8000` in dev **and** preview).
- `packages/ui-kit/tokens.css` is the shared token file for other surfaces.
- Build input is optional: `packages/protocol-runner/` and `kb/protocols/` are read
  at config load; absent → stub, no build failure.

## KNOWN ISSUES

- The demo payload has **no `earth_range`**, so the Earth line is not drawn today —
  the UI shows “verdict from the engine; range value not in this export” instead of
  inventing 60–100. Once A1 adds the field it renders automatically.
- With the API up and no `scenario-*.json`, `/api/scenarios` titles are the raw
  slugs; the picker prettifies them but the metadata is still missing.
- Card explanation is requested once per `scenario|crew|day` when Act opens; no
  retry button (reload to retry).
- A4's runner is bundled at build time from `kb/protocols/`; adding a protocol
  requires a dev-server restart. Its own stylesheet is injected at runtime so the
  app still builds if it disappears.
- In light theme A4's runner keeps its own dark surface (its tokens are scoped).
- Hash writes use `replaceState`, so Back leaves the app rather than stepping views.
- `apps/crew-tablet/dist/` is generated and **not committed** (see requests).
