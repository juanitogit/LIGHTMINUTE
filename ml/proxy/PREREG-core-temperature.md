# Preregistration · synthetic core-temperature sensitivity

Question: can a training-only circadian and activity adjustment reduce false high-temperature flags while preserving detection of an injected elevation?

Design decisions below are synthetic assumptions for a software experiment. The NASA HRP information request motivated 24-hour observation across activities. It does not specify the inputs, model or thresholds used here. [NASA RFI, opened November 14, 2026 Bogotá](https://www.nasa.gov/help-nasa-find-practical-ways-to-monitor-astronaut-body-temperature-in-low-earth-orbit/)

Use one independent simulated stream per seed (3000–3031), hourly over 14 days. Pair methods on exactly the same stream. Use days 1–7 for training and days 8–14 for reporting. One six-hour positive step begins at noon on day 11. Compare amplitudes +0.3 °C and +0.6 °C independently on the same underlying noise; run a separate no-step control for false flags. Scheduled exercise is 16:00–17:59 each day, sleep is 23:00–06:59, other hours are rest. The generating mean is 37 + 0.30 sin(2π(hour−9)/24) + 0.50 exercise − 0.10 sleep °C. Add Gaussian AR(1) noise with coefficient 0.6 and innovation SD 0.08 °C, starting from zero. Exercise and sleep labels are fully observed.

Compare raw temperature with residuals of per-stream ordinary least squares on intercept, sine and cosine of hour, exercise and sleep. Estimate coefficients on training hours and freeze. Initialize the same audited BaselineModel on each method's training mean and sample SD, then replay training with robust_update. Use model from commit 3242d419e752d65b0a5fb0c42d4e61e80ab43874, git blob 2086acd4869802cd48d7373dbb8edef4559d536b. Predict before updating each hourly observation. A high flag exceeds the upper end of the nominal two-sided 95% next-observation interval. For each method report control false flagged hours per observed person-day, broken down by activity as a fraction of control hours; event detection at least once within the six injected hours for each amplitude, median first-flag latency among detections and misses.

Predeclared favorable result: strictly fewer control false flags and at least as many detected events at both amplitudes. Otherwise report that the criterion failed. Output aggregated counts, paired seed-level evidence and software versions. No parameter or threshold tuning on report streams. Neither clinical sensitivity nor real sensor accuracy can be estimated here. Known weaknesses include alignment between generator and fitted model, perfect activity labels, fixed schedules, no missing samples and a single event onset time.
